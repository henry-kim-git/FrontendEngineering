# Plain Planner

『지속 가능한 프론트엔드 엔지니어링』을 공부하면서, 매주 읽은 원칙을 기준으로 AI 에이전트와 함께 플래너 앱을 개선해 나간 저장소예요.

메인은 프론트엔드 엔지니어링 공부이고, 그 과정에서 AI 에이전트에게 일을 맡기고 검토하는 경험도 함께 쌓으려고 했어요. 한 주에 한 가지 원칙씩 적용하고 PR로 남겼고, 각 PR 설명에 무엇이 문제였고 어떻게 바꿨는지 적어뒀어요.

## 기억에 남는 변화

- 725줄짜리 `planner.ts` 한 파일을 역할별 모듈로 나누고, 공개 API만 `index.ts`로 내보내도록 정리
- 모달마다 5~7개씩 흩어져 있던 `useState`를 리듀서 하나로 통합
- `localStorage` 접근을 `plannerRepository`로 감싸서 저장 방식이 바뀌어도 화면 코드는 그대로 두도록 변경
- 6주차에 Vitest를 도입해 순수 로직과 리듀서, 공용 컴포넌트 위주로 테스트 작성 (전체 화면 렌더 테스트는 일부러 제외)

## 기술

Next.js 16, React 19, TypeScript, Vitest, Testing Library

## 폴더 구조

```
app/              라우팅
src/
  app-shell/      앱 전체 레이아웃
  planner/        도메인 로직 (일정, 할 일, 알림, 날짜 계산)
  repositories/   저장소 접근
  hooks/          상태와 리듀서
  components/     공용 UI
  lib/            유틸
```

## 실행

```bash
npm install
npm run dev        # 개발 서버
npm run test       # 테스트
npm run typecheck  # 타입 검사
```

## AI 에이전트 활용

- 주차마다 공부한 원칙을 기준으로 개선할 범위를 정하고, Claude에게 작업을 맡긴 뒤 결과를 PR 단위로 검토
- `CLAUDE.md`에 프로젝트 구조와 규칙을 정리해 에이전트에게 전달하고, 문서와 실제 코드가 어긋난 부분도 리팩토링하면서 함께 맞춤
